# PPT 组件结构分析与组件库

以现有 PPT 为样本，拆解、分析和归纳常用组件，逐步构建可复用的组件库。制作时以人工选定的组件为主导，支持“核心方向与重点＋文献PDF＋选型JSON”，Word为可选材料；由Agent按需调用五个科研skill，完成阅读、图文提取、汇报层次及PPT制作。

## 下载与使用

从 GitHub 克隆仓库或通过 **Code → Download ZIP** 下载并解压。用浏览器打开解压目录中的 `library/index.html`，即可离线浏览组件、填写要求和导出选型 JSON。

公开版提供组件库、四色可编辑 PPTX 母版、渲染预览、制作脚本和使用文档。制作新汇报时，向 Agent 提供本次的选型 JSON、主题和材料。重建原始组件时，需要另行准备拆解文档中登记的参考素材。

## 后续工作方向

1. **组件拆解与归纳**：分析参考 PPT 中的组件结构，记录用途、布局、组成元素及来源页码。
2. **组件库构建**：在分析结果的基础上整理组件分类、样式及适用条件。
3. **人工选型与模型补充**：以人工提前选择的组件样式为主导，模型提供补充分析与适配建议。
4. **基于文献与材料制作 PPT**：围绕核心重点阅读PDF或Word，整理证据与汇报结构，按缺口补充网络资料、文献及配图。

以上记录项目目标与推进顺序。组件库负责浏览、人工选型、填写要求及导出JSON。用户将核心方向、JSON和PDF等材料交给Agent后，由Agent接着分析和制作；库内不上传材料、不连接模型或启动制作任务。

## 组件库（0.10.0）

当前有 46 个组件和 16 个可选变体。左栏「汇报页」下设「汇报样式1」至「汇报样式5」，每套包含首页、章节切换目录和结束页。正文按双栏并列、三栏并列、四类并列、机制与综合论证、时间线与进度、案例分析和参考文献分组。两页共用可折叠导航，初始展开首套汇报样式。

顶部「配色」可选蓝白、红白、绿白、紫白。每套覆盖全部 46 个组件和 16 个变体，提供 PowerPoint 渲染预览及可编辑原版和 X 占位母版。所选配色适用于本次任务，并随 JSON 交给 Agent。[配色与复用规范](docs/组件拆解与复用规范.md#四色配色)

已根据用户指定的5张参考图独立建立首批组件，不依赖现有skill：

1. 章节切换目录：唯一当前项高亮，其余浅灰；按条目数计算上下和行间净间距。
2. 政策需求双栏论证：政策总依据、左右证据和底部项目落点。
3. 方法与两层证据分析：左侧方法、右上处理证据、右下特征结果。
4. 原理与改进方法分析：基础原理、改进方案、方法特点和模型分类。
5. 应用指标与机制链分析：场景与现象、指标解释、三个节点的机制链。

第二批按新提供的4张参考图继续入库，累计9类组件、6个授权变体：

6. 三类并列与底部递进：栏内可有图或用小矩形，底部保持递进关系。
7. 三类并列与共同特征归纳：逐栏提炼特点，向下汇入共同归纳。
8. 总述拆分与三栏内容：顶部总述统领三栏，优先多层编号列表和图片加文字。
9. 问题—思路—技术三路线：三栏并列，每栏纵向对应；名称可换为成果、路线、方法等。

第三批按7张参考图新增7类结构，累计16类组件、10个可选变体：

10. 双因素作用与右侧图证：两组因素作用于结果，可用于正向、负向或混合影响。
11. 双类定义来源与底部图组：共同定义下两类并列，配来源条目和相关图组。
12. 双栏编号与分组条目：两大主题各有子主题，保留编号及文字层级。
13. 总述与双栏图文要点：总述统领两个视角，各栏有图、图解和要点。
14. 四栏并行与文字层级：标签不限定日期，局部图文按内容选择。
15. 发展时间线与政策治理：时间节点、文件依据、实施层级和并行任务分开表达。
16. 左右共同作用于中心：两侧相向汇入中央，下方可用图组或总结文字。

第四批新增四类问题与案例、三栏图证与底部总述、双路径手段与案例、单框虚线双栏、编号文献表、分支案例和纵向案例链。累计23类组件、12个变体。双路径可选递进箭头，分支案例可选左侧双行动与右侧效果。详见[分区与替换规则](docs/组件拆解与复用规范.md)。

- [打开离线组件目录](library/index.html)：原图对照、功能分区、目录数量演示和母版下载，无需启动服务。
- [阅读拆解与复用规范](docs/组件拆解与复用规范.md)：统一样式、逐区域功能和后续内容替换规则。
- [第二批组件拆解](docs/第二批组件拆解.md)：区分底部递进与共同归纳，规定模型栏内选择范围，提供变体导出命令。
- [第三批组件拆解](docs/第三批组件拆解.md)：双因素及正向占位、三种双栏、四栏图文、政策时间线和两侧汇入中心。
- [组件定义](library/components.json)与[主题定义](library/theme.json)：人工选型和固定结构的可机读记录。
- [原生PPT母版](library/templates/)与[实际渲染预览](library/previews/)：每类组件独立单页。

可编辑文字统一微软雅黑，内容页标题统一32pt加粗，基础蓝色统一为`#0046A5`，保留红黄强调。目录转曲装饰和图片内部的字体保留原图/原路径。

0.4版已统一全部15类内容页及10个变体的页框：纯白画布、顶部页标题、双层蓝色隔断、底部深蓝条，删除页码。正文通过已登记位移和少量装饰留白调整适配页头，保持实际字号和图片尺寸；章节目录沿用专用导航结构。原案例母版、X占位母版和实际预览均已同步，详见[统一页框与检查记录](docs/统一内容页底板与检查记录.md)。0.3任务可继续读取，重新导出时引用0.4母版。

组件库默认展示和下载[等字数X占位母版](docs/X占位母版与容量替换规范.md)。62种形式保留原文字量、段落、字号和图片框，原案例可切换对照。制作时逐框换成本次文字与图像，原字数作为容量参考，成稿重新渲染核验。

组件库提供授权变体、逐栏有图/无图选择及真实图片的等比绑定。已有原生填充、拼装和实际渲染引擎保留在`scripts/`，供接手任务的Agent使用；页面仅导出本次要求及组件说明，不执行这些制作步骤。

重建和验证方式见拆解规范；Python依赖见`requirements.txt`。修改母版后需更新实际预览和校验记录。

## 从选型导出到 Agent 制作

以全部入库组件为候选，在每次制作前选择优先组件、变体及模型可调整范围，再由Agent根据核心方向和实际资料分析、补充必要来源并分配逐页内容。

- [制作工作流与人工选型](docs/制作工作流与人工选型.md)：操作步骤、匹配规则、来源追溯、制作模块和当前能力边界。
- [制作任务填写模板](templates/制作任务填写模板.md)：填写本次原稿、听众、时长、优先组件和补充检索要求。
- [PDF文献驱动的Agent制作流程](docs/PDF文献驱动的Agent制作流程.md)：无Word输入、五个科研skill分工、原页图文提取、缺口检索、配图与最终验收。
- [PDF汇报交接提示词](templates/PDF汇报交接提示词.md)：核心方向和附件交给Agent时可直接使用。

当前目录支持组件多选、优先级排序、变体选择、当前草稿自动保存和JSON导出。详见[任务选型与Agent交接说明](docs/本次任务选型说明.md)。

1. 在组件库勾选优先排版、调整顺序并选择变体；未选组件自动作为备用。
2. 填写主题、听众、时长、页数及必要的补充要求。
3. 点击“导出任务 JSON”。再次打开同一浏览器中的同一入口时，当前草稿会自动恢复。
4. 将核心方向、JSON和论文PDF交给Agent；Word、数据和已有图片可选。Agent定向精读、综合证据、搭建汇报层次，再按选型制作。

JSON包含人工偏好、组件分组、首尾页角色、结构说明、母版路径、X占位容量、主题和制作约定。Agent从本项目或用户另附的文件读取母版与素材。恢复旧版草稿后，按当前组件库重建导出的交接信息。

直接打开组件库HTML即可离线选型与导出。已有本地HTTP入口 `http://127.0.0.1:8871/library/index.html` 同样可用，两个入口分别暂存当前草稿。[组件库HTML](library/index.html)

任务与组件目录的回归脚本分别见 [check_tasks.cjs](scripts/check_tasks.cjs) 和 [check_catalog.cjs](scripts/check_catalog.cjs)。[原生制作引擎](docs/PPT制作引擎检查记录.md)及[完整自动制作流程](docs/PPT自动制作流程检查记录.md)保留此前验证记录，后者对应历史版本的库内制作界面。真正制作PPT时，由Agent继续执行来源追溯、原生对象检查和实际渲染。

## 版本记录约定

- 每次完成一项可独立检查的修改后，核对改动并创建本地 Git 提交，提交说明写明修改内容。
- 原始资料与后续分析、组件资产和制作结果分开存放；不直接覆盖原始资料。
- 提交前检查待提交文件，避免混入临时文件、密钥或无关改动。
- 如需回退，先保留当前工作，再选择具体历史版本，避免丢失未提交修改。

常用查看命令：

```powershell
git status
git diff
git log --oneline
```
