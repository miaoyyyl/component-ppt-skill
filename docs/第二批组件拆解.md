# 第二批：三类并列、总分拆解与问题路线

版本：0.2.0。日期：2026-11-01。依据本轮4张用户参考图独立入库，沿用此前确认的蓝白、微软雅黑及红黄强调规范。

本批新增4类组件和6个可下载变体；累计9类基础组件、6个变体。以下“图1至图4”只指第二批参考图，原图文件按全库顺序保存为`reference-06.png`至`reference-09.png`。

## 四类结构如何区分

| 本轮参考 | 组件 | 主要关系 | 模型可选择的内容形式 |
| --- | --- | --- | --- |
| 图1 | BW-TRIPLE-PROGRESS-01 | 上部三类并列/相关；中部聚焦；底部递进/发展 | 每栏按内容选图文或内嵌小矩形；纯并列时取消栏间连线 |
| 图2 | BW-TRIPLE-COMMON-01 | 上部三类并列/相关；各自特点共同汇入总归纳 | 图文或内嵌小矩形；特点可以是问题、优势、条件或共同性质 |
| 图3 | BW-TRIPLE-DECOMPOSE-01 | 顶部总述与三栏之间是总分 | 优先多层编号列表、图片加文字；源流程作为可选结构 |
| 图4 | BW-PROBLEM-IDEA-TECH-01 | 横向三条路线并列，纵向问题、思路、技术对应 | 胶囊名称可用成果、路线、方法、方案等同层名称 |

**图1的底部递进与图2的共同归纳必须分开。** 三个共同特点不能因为数量相同而被连成发展链；发展节点也不能直接套成一个共同问题。人工先选关系组件，模型再在该组件已授权的栏内形式中补充判断。

## 共用的栏内选择规则

1. 先确认图片是否承担证据或解释职责，以及本次是否有合适、清晰、可追溯的图片。
2. 有对应图片时使用图文，按固定框等比适配；不同长宽比允许留白，不拉伸。
3. 没有合适图片时不强制配图，优先像图1中栏那样使用较小内嵌矩形，承载条件、要点、特征或局部判断。
4. 同一页可以有图栏、无图栏混排。外部三栏、栏头和主要层次继续固定。
5. 内部小矩形如果有箭头，需要实际内容支持其方向；只说明特征时可以使用无箭头要点框。
6. 上部仅为并列时，模型可选择无栏间箭头；有关联或互动时再保留相应连线。

每次选择建议登记：`componentId`、各栏`panelModes`、是否显示栏间联系、图片资产及哈希、选择理由、需要替换的槽位。组件ID由人工选择；模型的选择范围是本组件已授权的形式，不覆盖人工的关系选择。

## 图1：三类并列与底部递进

原生来源：`重点研发计划（太赫兹运用 蓝色）.pptx`，第8页。

上部各栏包含类名、对象/主题、解释及局部图文。中间蓝底黄字是三类内容共同聚焦的范围。底部左侧说明提供语境，右侧三个小矩形及连接表示发展、递进或阶段定位，不能当作三个独立问题列表。

已有原生形式：

- **参考结构**：第一、第三栏有图，第二栏是内嵌条件与要求框。
- **三栏均用内嵌小矩形**：第一、第三栏的图像位置替换为小矩形；中栏保留来源已有的内嵌结构。
- **三类仅并列**：保留各栏图文，取消上部栏间双向连接；底部递进结构不变。

模型还可逐栏组合，例如第一栏无图、第二栏保留原内框、第三栏有图。若要将原本无图的中栏改为有图，需提供本次真实图片，不能自动借用别栏图片作为新证据。

## 图2：三类并列与共同特征归纳

原生来源：`青年科学基金项目(等离子体).pptx`，第5页。

每栏的主体内容下方各有一条特点、局限或条件。三支向下箭头分别连接到同一条蓝底黄字总归纳，这层关系是“共同具有/共同说明”。本组件不会生成图1底部的横向递进节点。

已有参考图文形式及三栏内嵌小矩形形式。无图形式的小矩形采用相同宽度、高度与纵向位置，保留三栏比较的对齐关系。新框内的“条件、要点或特征”等文字是显式版式占位，不是科研结论。

## 图3：总述拆分与三栏内容

原生来源：`环境修复Cd污染修复.pptx`，第15页中与截图对应的区域。排除原页页头、背景介绍和标识，选中结构整体上移95px，内部尺寸及相对位置保持不变。

顶部渐变承载总述，下方三个栏头分别命名它的展开维度。三栏不要求机械等宽，保留原图为列表、图像和解释分配的比例。

- **多层编号列表**：主序号圆标、蓝色子标题、小矩形中的下级无序说明。编号表达主层次，无序符号表达同一子主题的要点。
- **图片加文字**：完整图或图组承担证据/解释，旁边用局部标题、条目及简短结论解读；不把图内每个细节机械抄成正文。
- **源流程**：只在内容确有过程关系时采用，保留在“参考结构”选项中。

离线目录默认选择“**编号列表／图文／编号列表**”。第三栏将来源流程中的四个既有步骤分为“检测与配比”“施用与监测”，没有新增实验结论。主序号为1、2，下级无序符号可选`◆`、`•`、`▪`、`–`，更换符号时同时指定其字体，避免继承旧符号字体导致乱码。

## 图4：问题—思路—技术三路线

原生来源：`联合基金(亚热带岩性森林 蓝色）.pptx`，第10页中与截图对应的路线矩阵。排除原章节页头、标识和页脚，结构整体上移31px居中，内部尺寸不变。

横向三栏是同层的成果、路线、方法或方案；纵向每栏均为：

```text
具体问题
    ↓
分析思路、测量或推导
    ↓
具体技术、方法、模型或路线产出
```

三个共用行标签帮助横向比较。每一栏必须先能纵向对应，再检查三栏同一行的语义层级。不能把三条路线理解成三个先后阶段。

“成果”是可替换的名称，不要求内容已经完成。提供了“路线一／二／三”和“方法一／二／三”两个标签变体；标题、胶囊尺寸和下方内容位置保持一致。预期方案不能因为使用此组件就写成已验证成果。

用户截图的每栏都有两支向下箭头。原始PPT缺少后两栏的第二支箭头，本版复制第一栏同款原生箭头补齐，并在`nativeAdditions`中记录来源和位移。

## 导出形式与记录

预置变体可直接在 [离线目录](../library/index.html) 选择和下载。组件本体、变体的预览、功能分区、槽位及下载文件同步切换。

从项目根目录导出部分栏无图的并列组件：

```powershell
python scripts/build_library.py --component BW-TRIPLE-PROGRESS-01 --panel-modes nested-text,nested-text,image-text --connection-mode parallel --output my-three-columns.pptx
```

提供真实图片时，先保存图片映射JSON，例如`{"2":"assets/本次图片.png"}`；图片路径相对该JSON文件。再使用`--panel-images 图片映射.json`，并将对应栏模式设为`image-text`。脚本原样登记图片字节与哈希，等比放入固定图框，不修改图内像素。

导出多层列表并更换无序符号：

```powershell
python scripts/build_library.py --component BW-TRIPLE-DECOMPOSE-01 --variant list-image-list --bullet "▪" --output my-decomposition.pptx
```

导出方法标签：

```powershell
python scripts/build_library.py --component BW-PROBLEM-IDEA-TECH-01 --variant methods --output my-methods.pptx
```

这些命令会同时保存`.selection.json`选择记录。脚本执行结构选择与导出，本身不调用模型、不解析Word；模型在真正制作时根据本次内容生成或补充这些选择。

| 递进终点 | 说明下一层次、目标或终点 | 简短节点 |
| 底部递进连接 | 表达发展或顺序，不用来连接无关的并列事实 | 方向固定，内容需有对应关系 |

### BW-PROBLEM-IDEA-TECH-01：问题—思路—技术三路线

| 区域 | 功能 | 后续替换 |
| --- | --- | --- |
| 共同对象或任务总述 | 限定三条路线共同处理的研究对象或总任务 | 1行蓝底黄字总述 |
