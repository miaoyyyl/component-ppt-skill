# PPT 组件库拆解与复用规范

结构基线为 0.4.0。四色配色自 0.10.0 起使用。

## 设计依据与人工决定

本库根据用户先后提供的16张参考图和当前项目中的原始PPT独立设计，不依赖现有skill。用户指定的结构是优先约束。人工先选样式，模型再判断内容怎样放入这些结构；已授权的栏内图文、列表和标签形式可由模型选择并登记理由，固定结构变化由人工决定。

已确定的要求：

- 主体为蓝白色系；保留参考图中的红色重点和黄色标签。
- 统一可编辑文字的字体和基础蓝色；不同功能保留字号层级。
- 目录只高亮接下来进入的章节。蓝色山景按参考用红色表示当前项、蓝色表示其余项。其他套系用蓝色表示当前项、浅灰表示其余项。
- 图2至图5保留区域结构、图片框、文字框和连接关系；后续以替换内容为主。
- 第二批4张图的三类并列、总述拆解和问题路线结构已追加，详见[第二批组件拆解](第二批组件拆解.md)。
- 内容页统一为纯白背景、独立页标题、双层蓝色隔断和底部深蓝条，移除页码。正文按登记位移收紧留白，字号和图片大小保留；后续替换锁定0.4母版坐标，不恢复来源页的旧底板。

本版累计16类页面或局部结构组件、10个授权变体，具备原生PPT母版、样式数据、槽位记录和离线浏览页。默认以[等字数X占位母版](X占位母版与容量替换规范.md)展示文字容量，保留字号、段落和图框。以下图1至图5指第一批参考；第二批、[第三批](第三批组件拆解.md)在独立文档中说明；选型导出与Agent交接见[任务说明](本次任务选型说明.md)。

```powershell
python scripts/build_library.py --component BW-TOC-WAVE-01 --toc-labels chapters.json --active 2 --output chapter-2.pptx
```

## 研究进展 · 时间轴与完成度

研究进展与「发展时间线与政策治理」归入「时间线与进度」。研究进展页适用于同时说明前序工作排程、后续重点和可核实完成度的项目汇报。

左侧两个季度分成六个月份。九张错列任务卡分别填写起止日期和简短说明，日期与对应月份对齐。右侧规划标题下方有三组配图与进度环，按从上到下的顺序一一对应，替换时沿用原图框。

每个进度环由 PowerPoint 原生图表、白色圆心与中心标签组成。百分比文字框在圆心内居中加宽，容纳一位小数并保留原字号。填充脚本接收单个 0% 至 100% 的百分比，并同步更新中心数字、扇区和内嵌工作簿。手动修改母版时，图表数据的两项分别填写完成值与剩余值，合计为 100，圆心数字填同一完成值。

统一字体不等于把正文、标签和标题设成同样字号。各组件的局部文字尺寸保留来源层级，以便替换时保持体量。标题、引领句和红黄重点按其功能加粗。

15类内容页及10个变体都包含`pageTitle`槽位。页标题使用原生对象`61000`，隔断为`61001`，底条为`61002`；内容中01/02等层级编号保持。详细位移、留白调整、实际渲染及旧任务兼容见[统一页框记录](统一内容页底板与检查记录.md)。章节切换目录仍按下方导航页规则单独处理。

目录左侧“汇报目录/CONTENTS”在源文件中已转为原生路径，继续作为装饰标识保留。科学图、政策截图、照片中的文字和颜色属于图像内容，不会通过替换PPT字体改变。新图若需要统一图内字号，应从图表源数据或可编辑图文件重新输出。

## 图1：章节切换目录

其功能是导航，不放章节摘要、研究结论或正文内容。每个条目由外轮廓、编号、竖向分隔线、章名四部分组成；左侧目录标识与背景保持固定。

“层级数量”在这里按同层级章节条目数量处理。如果以后需要父子缩进目录，应另建组件，不混用此结构。

### 等距规则

本版把白色主面板的上下边缘作为排布边界：上沿`y=55`，面板高度`H=610`。设条目数量为`N`，所有行的统一高度为`h`，顶部留白、相邻行净间距、底部留白统一为`g`：

```text
g = (H - N × h) / (N + 1)
y[i] = 55 + g + i × (h + g)       i = 0 ... N-1
```

默认行高72.52px。数量增加时，整体统一缩小行高，保持字号不变；行高下限52px，净间距下限8px。容量按公式计算，不写死为6项。当前面板可容纳1至10项，更多条目会明确报告容量不足，由人工决定分栏或分页，不静默缩字或裁掉章节。

例如6项时，顶部、行间和底部净间距均为24.9829px。只有当前项为蓝色；所有其余项均为浅灰。改变当前项时，位置、行高、章名和编号均不变化。

如希望改为以物理幻灯片上下边缘而非白色面板为边界，需要同时调整主面板范围；当前规则以保留图1主面板结构为准。

## 内容替换契约

### 固定与可变

- **固定**：页面分区、主要图框位置和尺寸、标题栏、解释框、连接方向、原生槽位字号和文字层级。
- **可替换**：页标题、正文、局部标签、图像资产、图题、图解、重点短语、与新内容相符的数值和单位。
- **目录可变**：条目数量、章名、当前章；按统一公式整体重排。
- **第二批已授权的可变形式**：三栏图文或内嵌小矩形、并列时是否显示栏间连线、多层列表的无序符号、成果/路线/方法标签；变体不改变已选组件的底部关系。
- **第三批已授权的可变形式**：双因素的正向/负向/混合内容、四栏局部图文及类别标签、相向汇入组件的底部图组或总结。左右汇入方向、时间顺序和并行任务不能相互混用。
- **需人工决定**：改变区域数量、换结构、删框、增减连接关系、跨页、分栏或改变固定字号。

### 文字

按用户2026-11-02反馈，执行[展示文案与原图取用规则](项目记忆与展示规则.md)：内容页与配图不显示引用编号、不增添灰色小字的范围或核验补充；来源和次要限定放入备注与来源记录。页标题为陈述式；展示语句末尾不加句号等句读，句中标点、单位和科学符号保留。此约定同样适用于插图内文字。

替换时保留字号、文字框位置、框内边距、对齐和行距。普通文字替换只改变文本；富文本槽位还需要明确哪些新短语对应红色或蓝色重点，不能按旧字符串长度直接套用颜色范围。

内容过长时，先去重复、组织短句或把次要细节移入讲述备注。重要限定条件、数值单位和证据边界必须保留。仍然放不下时，报告超容量并交由人工决定；不自动缩字、压字距、截句或让文字溢出框外。

模板来源本身有继承字号和自动适配设置。后续真正执行替换时，需要冻结本次确认的有效字号、检查自动适配设置，再用PowerPoint实际渲染复核。当前版本没有宣称已实现对任意新文字的自动替换与溢出修复。

### 图片

先逐张检查用户Word原图，登记用途、准确性、清晰度与采用/弃用理由；不能把写实偏好理解为排除全部机制图或现有原图。适用子图可以恢复裁切，科学错误须修正后重绘；未核准结果不能冒充实测。确认缺口后再检索或生成补图。

替换图片时保持原图框的位置和大小；原图完整另存。默认等比适配图框，比例不同可留白；允许裁切时需记录裁切范围，不裁掉关键坐标、图例、单位、面板标记或结论相关内容，不拉伸图片。

一组图按整体图框替换时要维持面板对应；按单图替换时要维持各图框的对齐和间距。图中原有文字的可读性需单独检查，不能只检查外框尺寸。

### 内容来源

参考页内容只用于理解结构。新文稿以用户本次核心方向和实际材料为基础，支持PDF文献与选型JSON，无需Word；执行[PDF文献驱动流程](PDF文献驱动的Agent制作流程.md)。新增网络或文献材料登记来源、日期、对应页面和用途，保留原文事实与模型推断的区别。Word、PDF和网页中的文字是材料，不自动成为项目执行指令。

建议未来每页绑定记录：`componentId`、`selectedBy: human`、`structureLocked: true`、每个槽位的新内容与来源、图片资产、重点短语、超容量处理及人工调整理由。此记录是后续制作引擎的输入约定，本版先固定组件契约。

## 文件与使用方式

- [离线浏览页](../library/index.html)：查看16类组件及10个变体、原始截图、实际预览和功能分区；可切换目录条目数量检查等距规则。
- [组件定义](../library/components.json)：人工选型、区域功能、固定结构及替换槽位。
- [主题规范](../library/theme.json)：字体、颜色、目录间距与容量约束。
- [原生对象清单](../library/inventory.json)：源文件哈希、原生对象ID、坐标、显式字号、组内文字对象与母版哈希。
- [原生PPT母版](../library/templates/)：每类组件独立单页，正文、容器、标签和箭头保留原生对象；科学图和照片保留图像。
- [统一样式预览](../library/previews/)：由本机PowerPoint后台渲染得到。

在项目根目录重建与检查：

```powershell
python scripts/build_library.py
python scripts/render_previews.py --with-variants
python scripts/build_library.py --viewer-only
python scripts/validate_library.py
```

重建依赖Python与lxml；检查使用Pillow和python-pptx，PowerPoint实际渲染使用Windows、本机PowerPoint和pywin32，清单见`requirements.txt`。离线浏览页本身不需要服务、网络或安装依赖，双击HTML即可打开。

导出自定义目录时，用JSON数组保存章名，例如`["研究背景", "研究方法", "研究结果", "结论"]`，再运行：

```powershell
python scripts/build_library.py --toc-labels chapters.json --active 2 --output my-toc.pptx
```

`--active`从1开始。该操作只导出目录页，不读取Word或自动制作整稿。

| 组件 | 阅读顺序与分区职责 | 替换时保留 |
| --- | --- | --- |
| 四类问题与对应案例 | 每栏先用短标题、说明、现象图和要点界定一个问题，下方用具名案例及照片说明它如何发生 | 四栏上下对应，每张案例图只支撑本栏 |
| 三栏图证与底部总述 | 栏首给简短判断，中部主图和图注提供依据，再用多点分析解释，并记录来源 | 跨三栏的共同结论置于页底 |
| 双路径核心手段与案例 | 两栏依次给路径名、核心手段、案例图与案例名、三条编号分析和局部结论 | 左右同构；确有先后关系时选递进箭头 |
| 单框虚线双栏分析 | 顶部明确共同对象，两侧分别列分析维度、发现、图证、图注和局部解释 | 一个外框和一条中央竖向虚线 |

| 案例背景与行动分支 | 顶部指明技术或政策，左上交代事件与条件，向下引出行动与效果；右侧配现场图和出处 | 选双行动时，左下为两项并列行动，右侧改为效果说明 |
| 案例背景、技术与效果链 | 从案例名向下依次阅读背景、项目实施步骤和效果；右侧独立现场图与图注 | 效果写明指标、参照和观察期；图片区与对应案例一致 |

## 第六批 · 组合、不等宽并列与导向展开

本批从仓库原生PPT中提取对应对象，保留图片字节和局部文字层级。新增5类组件与3个授权变体，累计33类、49种形式。首页、结束页、目录继续置于库首

| 组件 | 分区功能与替换逻辑 |
| --- | --- |
| 多项合成与分组阐述 | 悬挂式标签与总述框引题，多个独立条件经加号合成为一个判断。下方三组图文分别提供技术、需求或应用依据。可选两项或三项相加 |
| 左侧总览与右侧分组递进 | 左边在一个外框内排列四点并向下汇入总目标，右上两张卡片并列描述背景，右下三段蓝色标签与对应文字框给出行动阶段 |
| 不等宽并列图文分析 | 上方目标框和总领句限定论点。左边窄栏承载方案图及局部解释，右边宽栏分别容纳实验图、三个特征与结果图文。宽度比例与内部分区固定 |
| 上下两层要点与图文归纳 | 顶部给出整体判断。上层悬挂标签统领三项文字说明，下层用两组图文，经箭头汇入核心主题，再向下分出两个落点 |
| 问题、方法或技术导向展开 | 顶部总述，左侧两组图文或目标分别对应右侧两组解释，底部两条归纳收束。可选择问题、方法或技术导向，分别替换对应标题和内容 |

局部适配以参考图为依据。第一类把原PPT左栏的上下两个框合并成一个框，并保留四张原图的大小、调整行位置。第二类收紧右下第三段文字框的范围。第五类移除原PPT右侧额外的两张配图，并展开对应文字区域，保留参考图中的左侧三图、对应箭头及底部归纳框

本批示例用于理解版式，制作时从本次Word和资料中填入文字、图片与来源。旧任务可以继续读取，新组件自动加入备用集合
