# 本次任务：选型、导出与 Agent 交接

更新于 2026-11-07。组件库 0.10.0 共 46 类组件和 16 个变体，支持蓝白、红白、绿白和紫白。把核心方向、PDF 和 JSON 交给 Agent 后即可开始制作，Word 为可选材料。

## 页面操作

1. 在顶部选择本次配色，在左栏展开汇报样式或正文分类，再勾选优先组件。悬停可预览当前配色的版式，未选组件作为备用。
2. 在优先卡片中上移、下移排序，选择参考结构、指定变体或由模型按内容选择。卡片采用紧凑图文布局，保留预览按钮。
3. 填写任务名称、听众、时长和页数范围。原稿说明、必须保留内容、资料与文献范围在可选区域填写。
4. 点击主要按钮“导出任务 JSON”。将核心方向、JSON和文献PDF交给Agent，Word、图片、数据及其他材料可选。
5. 同一浏览器中的同一入口会自动恢复当前草稿。点击“新建任务”可开始一份空白选型。

页面不提供Word上传、模型连接、任务启动、成稿下载或自动渲染区域，也不请求模型或任务接口。离线双击`library/index.html`即可使用，已有HTTP入口也可继续浏览。

默认展示[等字数X占位母版](X占位母版与容量替换规范.md)，可切换查看原案例版式及已公开的原始参考图。每个母版和变体可单独下载。

## JSON交接内容

原有`ppt-production-task / schemaVersion: 1`格式保持兼容，新增`handoff`说明块：

| 字段 | 内容 |
| --- | --- |
| `brief` | 任务名称、听众、时长、页数、原稿说明、必须保留内容及检索范围 |
| `preferredComponents` | 人工优先级、组件ID及选定变体 |
| `fallback` | 按总库计算的其余备用组件 |
| `workflow` / `constraints` | Agent接手后的自动分析、资料补充、逐页分配和结构保护约定 |
| `handoff.execution` | `agent-after-user-handoff`，明确交给Agent后执行 |
| `handoff.materials` | 原稿和图片单独提供；旧任务材料引用的解释 |
| `handoff.researchWorkflow` | PDF优先、Word可选、五个科研skill分工、流程/脚本入口与证据链标识 |
| `handoff.library` | 组件库版本、项目相对路径及母版访问要求 |
| `paletteId` / `handoff.theme` | 本次所选配色、字体、红黄强调和目录等距规则 |
| `handoff.components` | 优先和备用组件的用途、论证关系、固定结构、允许形式、母版/预览路径、文件哈希、文字容量及替换槽位 |
| `handoff.instructions` | 供Agent接手的材料、选型、来源、制作、检查和Git约定 |

人工指定变体时，交接信息只列出该形式；自动选择和备用组件保留其已登记的形式。模型仍需根据内容关系选择，不强制选中组件都出现。

JSON保存配置和结构说明，不包含Word、图片或PPTX文件本体。母版路径以组件库项目根目录为基准。Agent可以访问本项目时直接读取；在其他环境执行时，需要另附相应母版、素材及必要说明。不能仅凭JSON描述重画并宣称保留了原结构和字号。

## 草稿与旧任务

离线文件页面与 HTTP 页面的草稿分别保存。新建任务会切换当前草稿，历史记录仍保存在浏览器存储中。已导出的 JSON 可直接交给 Agent 使用。

恢复有效的旧版草稿时，保留原名称、选型、优先级、变体、备注和材料引用。旧 `documents` 用于按文件名和哈希核对实际提供的材料。重新导出时，交接字段 `handoff` 由当前组件库重建。

Agent 制作及项目功能修改按约定提交本地 Git。

## 交给Agent后

可以连同文件给出这句话：

> 请读取本次JSON和附带材料，以人工优先级和变体为主导，完成内容分析、必要的资料与文献补充、逐页方案及可编辑PPT制作；保留组件结构、字号和位置，实际渲染检查，并提交本地Git。

Agent应从真实材料建立内容和证据关系，选择组件、逐框替换本次文字与图像，输出PPTX、实际预览、来源和检查记录。库内案例图像与结论仅用于理解版式，不作为新项目证据。

无Word任务见[PDF文献驱动流程](PDF文献驱动的Agent制作流程.md)。已有JSON可直接交给Agent，使用当前项目流程；重新导出会附带新的researchWorkflow。核心方向可写在对话中，Agent记录到本次research-task.json，无需增加用户填写表格。
